架构说明：数据层采用"工厂 + 多源仓库 + 门面"三段式设计。
  • 数据源层：10 个独立数据源覆盖 K线、实时行情、板块、买卖盘、新闻等场景，东方财富为主源，腾讯/新浪为备用源，AKShare 提供通过 HTTP 调用的 Python 数据能力。
  • 仓库层：StockDataSourceFactory 负责数据源实例化；MultiSourceStockRepository 实现自动故障转移与负载均衡；EnhancedStockDataProvider 做增强处理；最终由 StockDataFacade 对外暴露统一接口。
  • 缓存层：SmartStockCache 支持 TTL 与预热策略，StockNameTrie 用前缀树实现快速名称匹配，HttpClientProvider 提供 OkHttp 单例复用连接，TradingCalendar 提供交易日历支持。
  • 调用方：StockQueryEngine 作为核心调度器统一对接数据门面，供服务层与远程数据服务调用。

流程说明：意图识别采用"识别器 + 处理链"模式，支持多种输入形式。
  • 意图识别：IntentRecognizer 先判断是否为 AI 意图，若是则直接走 AiIntentHandler；否则进入 IntentProcessorChain 处理链。
  • Handler 链：按优先级依次尝试代码识别 → 指数识别 → 前缀树名称匹配 → 普通名称匹配 → 模糊名称匹配 → 通用兜底，任一 Handler 匹配成功即短路返回。
  • 查询执行：匹配结果交由 StockQueryEngine 调度，经数据门面 → 多源仓库 → 数据源获取数据，中间经过 SmartStockCache 智能缓存加速。
  • 数据返回：结构化数据（K线/实时行情/板块/快照）最终交由 UI 渲染展示。

ER 关系说明：Room 数据库由 StockDatabase 主数据库承载，StockDatabaseManager 统一管理。
  • DailySnapshotEntity：每日快照实体，存储股票日 OHLCV 数据，是核心数据表，与板块记录、AI 选股、自选股均有关联。
  • SectorDailyRecordEntity：板块日记录实体，区分概念板块与行业板块，记录涨跌幅、成分股数量、资金净流入。
  • StrategyTradeOrderEntity：策略交易订单实体，记录策略名、订单类型、价格、数量、状态。
  • AiSelectedStockEntity：AI 选股实体，记录选股策略、评分、选股理由，与策略订单关联。
  • UserWatchlistEntity：用户自选股实体，支持分组与排序。
  • 辅助组件：StockDataCenter 提供热点板块查询与股票快照；DataExportImport 负责数据导入导出；ChinaMarketTradingHours 判断 A 股交易时间；AppBackgroundRunner 执行后台任务。

刷新流程说明：实时行情采用"策略驱动 + 多源兜底 + 通知订阅"模式。
  • 策略配置：RefreshPolicy 定义刷新间隔、交易时段判断、网络条件等策略；StockAutoRefreshManager 根据策略启动定时器。
  • 交易时段判断：ChinaMarketTradingHours 判断当前是否为 A 股交易时段，交易时段高频刷新，非交易时段进入低频轮询以省电。
  • 多源兜底：RealtimeDataAccessor 按 RealtimeConfig 配置的优先级依次尝试东方财富 → 腾讯 → 新浪，全部失败则回退缓存数据。
  • 数据处理与通知：RealtimeDataProcessor 处理价格、涨跌幅、成交量等指标，PriceUpdateNotifier 通过订阅模式通知所有 UI 订阅者（行情页/自选股/详情页），同时更新 SmartStockCache 缓存。
  • 循环刷新：UI 刷新完成后根据策略决定是否继续下一轮刷新，直至用户离开页面或主动停止。
