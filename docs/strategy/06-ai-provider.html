关键点：

2. Provider 健康探测与故障转移

定时探测 → 标记健康/不健康 → 请求时跳过不健康 → 全部不健康时降级AiProviderPool.kt / AiProbe.kt

AiProviderPool 通过 AiProbe 对多 Provider 执行健康探测（HEALTH_PROBE_TIMEOUT_MS=5000），动态维护健康状态并实现故障转移。

关键点：
  • 健康探测超时 HEALTH_PROBE_TIMEOUT_MS = 5000，由 AiProbe 执行。
  • 探测与请求两个阶段联动：探测结果写入健康状态表，请求阶段读取该表跳过不健康节点。
  • 请求失败时即时标记 UNHEALTHY，触发故障转移到下一个 Provider，形成动态反馈闭环。
  • 全部不健康时进入降级策略，保证系统可用性而非完全失败。

3. 流式 vs 非流式响应处理

两种模式分支处理OpenAiCompatibleProvider.kt

OpenAiCompatibleProvider 支持 streaming 与非 streaming 两种模式，分别走 handleStreamResponse（SSE 解析）和一次性 JSON 解析路径。

关键点：
  • 流式模式通过 handleStreamResponse 处理 SSE（Server-Sent Events），逐行解析 data: 行。
  • 流式支持增量回调，客户端可实时渲染；遇到 data: [DONE] 结束流并汇总。
  • 两条分支都必须在 finally 中关闭 ResponseBody，防止 OkHttp 连接池泄漏。
  • OkHttp 使用连接池管理，流式与非流式共享连接复用机制。

4. Agent 管道 max_tokens 配置矩阵

各 Agent 与模式的 token 配置OpenAiCompatibleProvider.kt

Pipeline 中不同 Agent 节点使用差异化 max_tokens 配置：Agent 1-3/D=4096, Agent 4-5=6144, Agent 6=8192；JSON mode=6144, Chat mode=4096。

配置矩阵：
  • Agent 1-3 / Agent D：max_tokens = 4096，用于轻量分析与数据提取任务。
  • Agent 4-5：max_tokens = 6144，用于深度分析与综合推理任务。
  • Agent 6：max_tokens = 8192，用于最终生成任务，输出空间最大。
  • JSON mode：max_tokens = 6144，保证结构化 JSON 输出完整。
  • Chat mode：max_tokens = 4096，自然语言对话场景。
