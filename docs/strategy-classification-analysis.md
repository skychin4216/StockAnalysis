# 策略分類分析

## 一、現有三個 Tab 的定位與區別

| 維度 | 🤖 短線量化 | 📈 中線量化 | 🎯 量化選股 |
|------|------------|------------|------------|
| **持倉週期** | 固定 3 天 | 可選 1/3/10/30/50/100 天 | 無持倉（僅篩選） |
| **最大持倉** | 3 只 | 5 只 | 無限制 |
| **Pipeline** | Zipline Pipeline + AI精選 | SimulationTradeEngine / DAG Pipeline | 直接調用策略引擎 |
| **賣出規則** | 硬止損-8% / 時間平倉10天 | AutoSellEngine 智能賣出 | 無賣出 |
| **建倉** | 自動建倉 + 騰籠換鳥 | 手動/自動建倉 + 騰籠換鳥 | 無建倉 |
| **AI 精選** | 有（AIPredictionEngine） | 有（AIPredictionEngine） | 無 |
| **主力資金過濾** | 有（SmartMoney >= 55） | 有（SmartMoney >= 55） | 無 |
| **Agent 分析** | 支援六智體/七智體 | 不支援 | 無 |
| **回測** | 30交易日歷史回測 | 回溯優化 + 參數擬合 | 無 |
| **Topology** | ShortTermUseCase（4 Stage） | MidTermUseCase（4 Stage） | 無 |

### 核心區別

- **短線/中線量化** = 完整交易系統（篩選 → AI精選 → 建倉 → 持倉管理 → 賣出）
- **量化選股** = 策略信號查看器（僅執行策略篩選，展示結果，不做交易）

## 三、短線量化 vs 中線量化 — 策略使用問題

### 當前問題：兩者使用完全相同的策略池

短線量化和中線量化都使用 **全部已啟用策略（排除 ai_prediction）**：

```kotlin
// 短線量化（ShortTermQuantFragment:313）
if (!eng.isEnabled(strategy.id) || strategy.id == "ai_prediction") continue

// 中線量化（MidTermQuantFragment:207）
val strategies = eng.getStrategies().filter { eng.isEnabled(it.id) }
```

**問題**：
1. 短線量化會用到低估值、基本面篩選等長線策略 → 信號意義不大
2. 中線量化會用到尾盤低吸、早盤追漲等超短線策略 → 已經錯過最佳時機
3. 兩者的策略篩選結果趨同，缺乏差異化

### 建議修復

短線和中線應使用不同的策略子集：

| Tab | 應使用的策略 | 不應使用的策略 |
|-----|------------|--------------|
| **短線量化** | 高開高走、換手率活躍、熱點驅動、龍頭輪動、放量突破 | 低估值、基本面篩選、均線金叉、布林帶突破 |
| **中線量化** | 均線金叉、布林帶突破、RSI背離、AI量化選股、低估值 | 尾盤低吸、早盤追漲、換手率活躍 |

## 四、四週期策略體系設計（建議）

### 總體架構

```
策略 Tab（5 個子 Tab）
├── ⚡ 超短線（持倉 1 天，T+1 賣出）
├── 🤖 短線量化（持倉 3 天）
├── 📈 中線量化（持倉 10-30 天）
├── 💎 長線量化（持倉 30-100 天）
└── 🎯 執行策略（獨立策略按鈕：龍頭輪動、AI精選等）
```

### 各週期定義

| 週期 | 持倉 | 適合場景 | 策略特點 |
|------|------|---------|---------|
| **超短線** | 1 天 | 强势市场、板塊輪動快 | 尾盤低吸、早盤追漲、日内動量 |
| **短線** | 1-3 天 | 震荡市、板塊輪動 | 放量突破、換手率活躍、熱點驅動、龍頭輪動 |
| **中線** | 5-30 天 | 趋势市、行情启动初期 | 均線金叉、布林帶突破、RSI背離、AI綜合選股 |
| **長線** | 30-100 天 | 下跌末期、价值回归 | 低估值、基本面三層篩選、機構增持 |

### 可行性評估

**完全可行**，理由：

1. **現有策略已覆蓋全部週期** — 13 個策略天然分佈在超短線到長線各週期
2. **引擎架構支持** — StrategyEngine 已有 `runAllWithData()` 方法，可傳入策略子集
3. **Pipeline 支持不同 config** — ShortTermUseCase 和 MidTermUseCase 已經證明了 config 差異化的可行性
4. **僅需調整分類邏輯** — 在策略上增加 `holdingPeriod` 屬性，Tab 根據週期過濾策略即可

### 實現路徑

1. **Strategy 增加週期標籤** — 在 `Strategy` 介面增加 `holdingPeriod: HoldingPeriod` 屬性
2. **StrategyCategory 擴展** — 增加 `HoldingPeriod` 枚举（ULTRA_SHORT / SHORT / MID / LONG）
3. **Tab 過濾** — 各 Tab 根據 `holdingPeriod` 過濾策略子集
4. **量化選股 Tab 改造** — 將策略按週期分列顯示，每列可獨立執行

### 風險與注意

- **超短線需要即時數據** — 盤中才能執行，離線數據無效
- **長線策略信號少** — 低估值/基本面策略需要較多數據，觸發頻率低
- **策略共用問題** — 同一策略可能同時適合短線和中期（如放量突破），需要靈活標記
