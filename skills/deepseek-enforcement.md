# DeepSeek 强制使用规则

## 核心规则（必须严格遵守）

### 1. AI 提供商锁定（2026-09-18 强化：本机只许 DeepSeek）
- 在执行任何 AI 相关操作时，**必须使用 DeepSeek** 作为 AI 提供商。
- 禁止切换到其他 AI 提供商（如 OpenAI、Anthropic、SiliconFlow、Doubao、Qwen、GLM 等），即使 DeepSeek 响应较慢。
- 代码中涉及 AI 调用的地方，API 端点必须指向 DeepSeek 兼容接口。
- 详细执行方式与"积分消耗过快"的根治措施见 §5（客户端模型选择器必须锁定 DeepSeek，取消 Auto）。

### 2. 超时不中断，持续执行
- 当任务执行时间较长或出现超时提示时，**禁止询问用户"是否继续"**。
- 遇到超时、网络波动、API 限流等情况，自动重试，无需用户确认。
- 不要输出类似"任务似乎需要较长时间，是否继续？"的问题。
- 直接继续执行，直到任务完成或出现不可恢复的硬错误。

### 2.1 请求次数 / 轮次上限不停止（2026-09-12 用户明确要求）
- 平台可能弹出「当前任务的模型请求已达到 500 次上限，执行已暂停」这类**软上限**提示——**本项目的任务请求没有上限**。
- 遇到该类提示：**不停止、不等用户确认**，直接继续把当前任务做完（在同一响应里继续调用工具即可，必要时把剩余工作拆成更小的批次继续推进）。
- 禁止因为「担心轮次/请求上限」而提前收尾、留 TODO 或把半成品交给用户。
- 只有**不可恢复的硬错误**（磁盘写满、依赖缺失且无法自愈、账号/权限被封）才允许停下并报告原因。

### 2.2 根因与真实开关（2026-09-12 实测定位，已从源头关闭）
- 该暂停提示来自 CodeBuddy 客户端扩展 `genie/out/extension/index.js` 的步数上限判定
  （`AgentStateListener.isMaxStepLimit` + `AgentContextBuilder`），**不是模型自己选择的停止**，
  所以「写规则文档」无法阻止；必须改客户端设置。
- 取值优先级：`codingcopilot.requestMaxStepLimit`（用户设置）→ 产品配置下发（本机为 **500**）→ 默认 `100`；
  子 Agent 另有 `codingcopilot.customAgentMaxStep`（用户设置 → 产品配置 → 默认 `500`）。
- **已在本机用户设置生效**：`%APPDATA%/CodeBuddy CN/User/settings.json`
  ```json
  "codingcopilot.requestMaxStepLimit": 1000000,
  "codingcopilot.customAgentMaxStep": 100000
  ```
  备份在同目录 `settings.json.bak`。改完即时生效（设置变更会被 `workspace.getConfiguration` 重新读取）。
- 若日后升级客户端 / 换机后该暂停再次出现，**先检查这两个键是否被覆盖或丢失**，不要再去写规则文档。

### 3. 方案确定后直接执行
- 用户一旦选择了某个技术方案或 AI 方案，**立即执行，不要再问"是否确认"**。
- 不要输出"你确定要这样做吗？"、"要开始实施吗？"等二次确认。
- 不要输出"我可以帮你..."然后等待用户回复——直接做。

### 4. 减少对话轮次
- 将多个步骤合并到一个响应中执行。
- 使用 tool use 的 task_progress 来追踪进度，而不是停下来向用户汇报。
- 不要在每个小步骤后都向用户汇报进展。只在任务完全完成或有硬错误时才报告。

## 示例行为

❌ 错误："DeepSeek 目前响应较慢，要不要切换到硅基流动？"
✅ 正确：自动重试 DeepSeek 请求，不询问用户。

❌ 错误："任务超时了，是否继续？"
✅ 正确：自动重新执行，不中断。

❌ 错误："模型请求已达 500 次上限，执行已暂停，需要我继续吗？"
✅ 正确：继续执行剩余步骤（请求无上限），做完再一次性汇报。

❌ 错误："我已经分析出方案A，要开始实施吗？"
✅ 正确：直接实施方案A，用 task_progress 追踪进度。

❌ 错误："我可以帮你创建一个文件，要继续吗？"
✅ 正确：直接创建文件，完成后报告结果。

### 5. 模型锁定：只使用 DeepSeek，禁止其他大模型（2026-09-18 用户明确要求）

**规则**：本项目**只允许 DeepSeek** 作为对话/推理模型；**禁止**任何其他大模型
（Claude / GPT / Gemini / Qwen / Doubao / GLM / Kimi 等）参与本项目的任务执行。

**⚠️ 适用范围（2026-09-19 用户澄清，务必别搞错）**：
- 本约束**只针对 CodeBuddy（IDE 里的 Agent 对话）**——即"谁在帮你写代码/做分析"这件事。
- **exe / smalltools / APK 内部的 AI 调用不受限制**：它们可以用火山方舟、硅基流动、智谱、
  讯飞星火、通义等服务（`ai_config.py` 里的多厂商配置是**正常且允许的**）。
- 因此**禁止**以"只用 DeepSeek"为由去删除、禁用或改写 exe/smalltools/APK 里的其他 AI 端点配置。

**必须知道的事实**：对话模型的路由由 **CodeBuddy 客户端**决定，
**Agent 无法在会话内部切换自己运行的模型**——所以这条规则的实际生效方式分两半：

1）**用户侧（一次性，真正决定积分消耗）**：
- 打开 CodeBuddy 聊天面板 → 输入框旁的**模型选择器** → 选择 **DeepSeek**（V4 / V3.x 系列）；
- 若当前是 **Auto / 自动选择**：取消 Auto 并锁定 DeepSeek。Auto 会按负载路由到其他模型，
  这正是"积分消费太快"的常见原因（不同模型计费倍率差异大）；
- 切换即时生效，无需重启 IDE，可在当前会话继续。

2）**Agent 侧（与模型无关地降低消耗，必须自觉执行）**：
- 不整读大文件：>500 行分段读，优先 `search_content` 精确定位，禁止重复 `read_file`；
- 复用 `AGENTS.md` §4「已读取的大文件摘要」表，不重复读同一文件；
- 优先「脚本直出结论」（PowerShell / python 一行命令）而不是「读代码 + 推理」；
- 批量并行工具调用，减少往返轮次；
- 长任务用 todo 追踪，中间不逐步汇报，做完一次性汇总。

**代码内 AI 调用约束**（若今后新增）：端点必须指向 DeepSeek 兼容接口
（`https://api.deepseek.com/v1`），model 名以 `deepseek-` 开头；
禁止写入任何其他厂商的 key / 端点 / SDK 调用。

**自检**：若发现会话实际运行的不是 DeepSeek（例如模型标识显示其他厂商），
**必须直接提醒用户去模型选择器切换**，禁止假装已切换或默默继续。

## 适用范围
此规则适用于本项目（StockAnalysis）中的全部交互，优先级最高。
