# 预警 Tab · BBI 买入窗闸门 + 信号评分 + 收益率对比 + 系统悬浮窗 实施方案

## 1. 摘要（Summary）

在已交付的「⚠ 预警」Tab（[短线预警Tab方案.md](file:///d:/Stock/StockAnalysis/.trae/documents/短线预警Tab方案.md)）基础上，按用户追加需求做 4 项增强：

1. **BBI 前提闸门**：`BB 均线（BBI的MA）趋势向上 且 BB 在其均线上方` = **买入空间开启**，这是买入的前提。
2. **信号评分**：每根 K 线上命中的**买入指标（B1..B5）各 +20 分**，满分 100；分数越高买入信号越强。BBI 窗口关闭时该根买入评分强制为 0 并灰显。
3. **系统悬浮小浮窗**：预警页新增开关；开启后**退出 App** 时在系统层出现小浮窗，滚动显示**持仓股**（= 做T页持仓池）的「信号评分 + 买入/卖出/持仓」；**点击浮窗**展开小窗口，列出所有持仓股**当前价格 + 买卖建议**，带「更新」按钮重新拉数判定。
4. **收益率对比**：软件内买入/卖出列表**之前**插入收益率卡，展示「信号配对策略收益率 vs 买入持有收益率」对比。

**口径不变**：仍为 60 分钟（1H）K 线、末 120 根（≈30 交易日）展示、无未来函数、信号在 i 根收盘确认。

## 3. 核心口径定义（决策完备）

### 3.1 BBI 买入窗（前提闸门）

```
buyWindowOpen[i] = v(bbi,i) && v(bbiMa,i) && v(bbiMa,i-1)
                   && bbiMa[i] > bbiMa[i-1]        // BBI 均线趋势向上
                   && bbi[i]   > bbiMa[i]          // BB 在其均线上方
```
- `v()` = 该点位非 NaN 且索引合法（复用引擎已有私有 `v`）。
- `buyWindowOpen[0] = false`（无前值）。
- **硬闸门**：当 `buyWindowOpen[i] == false` 时，买入信号**仍然列出**（便于复盘），但 `Signal.score = 0`、`Signal.windowOpen = false`，UI 该行灰显并标注「窗口关」。
- `AlertParams.requireBbiWindow: Boolean = true` 控制是否启用该闸门（关闭时窗口仅作展示、不影响评分剔除）。

### 3.2 信号评分

```
barScore[i] = 20 × |{ B1,B2,B3,B4,B5 在 i 根触发 }|          // 0 / 20 / 40 / 60 / 80 / 100
若 requireBbiWindow && !buyWindowOpen[i]  →  barScore[i] = 0  // 硬闸门
lastScore   = barScore[n-1]                                    // 浮窗用「末根评分」
```
- **X1 不计分**：X1 的两个分支分别是「触及 A 线支撑」与「BB 上穿均线」，后者与 B5 重叠，避免重复计分；X1 仍作为买入信号出现在列表与主图。
- 卖出信号 `Signal.score = 0`（列表显示「—」）。

### 3.3 收益率对比（区间内信号配对模拟）

区间 `from = max(0, n-120)`，`to = n-1`（与展示的末 120 根一致；全用**收盘价**成交，T 日信号在本根收盘成交，符合本 Tab 既有展示口径）。

模拟规则（单边做多，最多一仓）：
```
holding = false; entry = 0.0; returns = []
for i in from..to:
    if !holding && 存在 index==i 的买入信号 && buyWindowOpen[i]:   // 硬闸门同样约束建仓
        entry = close[i]; holding = true
    else if holding && 存在 index==i 的卖出信号:
        returns += (close[i] / entry - 1); holding = false
if holding: returns += (close[to] / entry - 1)                     // 末根强平
```
- 组合收益：`strategyReturnPct = (Π(1+r_i) - 1) × 100`。
- `buyHoldReturnPct = (close[to]/close[from] - 1) × 100`。
- `excessPct = strategyReturnPct - buyHoldReturnPct`。
- `trades` = 平仓笔数；`winRatePct` = 盈利笔数 / trades × 100（trades=0 时为 0）。
- **扣费开关** `includeCost=false`（默认毛收益）。开启时每笔往返扣 `(1-commissionRate) × (1-commissionRate-stampDutyRate)`，`commissionRate=0.00025`、`stampDutyRate=0.0005`。
- 同根同时有买卖信号时：**先判买后判卖**（因 `else if` 结构，一笔只做一次决策）。

### 3.4 浮窗建议判定（末根）

```
sellAtLast = 末根(index=n-1)存在卖出信号
score      = lastScore
win        = buyWindowOpen[n-1]
advice = when {
    sellAtLast            -> "卖出"
    win && score >= 40    -> "买入"
    win && score >= 20    -> "关注"
    !win                  -> "观望"
    else                  -> "持仓"
}
```
- 浮窗主行展示：`名称 评分 建议`；展开面板展示：`名称 现价 涨跌幅 评分 建议`。

### 3.5 「预警股 = 持仓股」

直接取 `SsaT0PoolStore.load(ctx)`（做T页「📋 持仓池」模式维护的池）。池为空 → 浮窗不展示（服务自检直接 `stopSelf()`）。

### 4.4 新建 `strategy/ssa/SsaAlertBatch.kt`

```kotlin
object SsaAlertBatch {
    /** 持仓池 → 逐票拉 200 根 1H → analyze → 合并实时行情 → OverlayRow（单票异常隔离） */
    suspend fun run(
        ctx: Context,
```

### 4.6 新建 `service/SsaAlertOverlayService.kt`

```kotlin
class SsaAlertOverlayService : Service() {
    companion object {
        const val ACTION_START / ACTION_STOP / ACTION_REFRESH
        const val NOTIFICATION_ID = 9002
        const val CHANNEL_ID = "stock_alert_overlay"
        fun start(ctx: Context)   // 先做权限/开关/池 三重自检，不通过直接 return
        fun stop(ctx: Context)
        fun refresh(ctx: Context)
    }

```
- **权限/开关自检（`start()` 与 `onCreate()` 双重）**：
  `Settings.canDrawOverlays(ctx)` && `SsaAlertStore.isOverlayEnabled(ctx)` && `SsaT0PoolStore.load(ctx).isNotEmpty()`；任一不满足 → 不 `startForeground`、直接 `stopSelf()`。
- `onStartCommand`：`ACTION_START` → `startForeground(...)` + `startForegroundService` 后 5s 内必须落地；`ACTION_STOP` → 移除视图 + `stopForeground(STOP_FOREGROUND_REMOVE)` + `stopSelf()`；`ACTION_REFRESH` → 触发一次重算。
- 返回 **`START_STICKY`**（被系统回收后恢复）；`onTaskRemoved` **不** `stopSelf`（用户"退出软件后浮窗出现"要求常驻）。
- 通知：channel `stock_alert_overlay`（IMPORTANCE_LOW、`setShowBadge(false)`）；点击 → `PendingIntent` 打开 `MainActivity`。
- **不取 WakeLock**（浮窗为被动展示）。
- 数据流：
  1. `onCreate` → 先 `render(SsaAlertStore.loadRows(ctx))`（本地缓存，秒开）。
  2. 若缓存为空或 `updated` 距今 > 10 分钟 → `refresh()`。
  3. `refresh()`：`scope.launch { view.setUpdating(true); rows = SsaAlertBatch.run(ctx, pool); SsaAlertStore.saveRows(ctx, rows); view.render(rows); view.setUpdating(false) }`（`SsaAlertBatch.run` 内部已是 IO）。
  4. **定时刷新**：协程 loop（`delay(5 * 60_000L)`）；仅当「A 股交易时段」才真正重算（private `isTradingTime()`：周一~周五 且 09:30–11:30 或 13:00–15:00），非交易时段跳过。
  5. `onDestroy`：`scope.cancel()` + `view.detach(wm)`。
- 「更新」按钮 → `onUpdate = { refresh() }`。

## 6. 假设与决策（Assumptions & Decisions）

> 本环境未提供 `AskUserQuestion` 工具，故把关键口径在此显式列明，供用户复核时纠正。

1. **BBI 买入窗 = 硬闸门（评分置 0 + 灰显），而非过滤掉信号**（依据："这是前提"）。若用户想要"窗口关就完全不列出买入信号"，只需把 §3.2 改为丢弃信号（一行改动）。
2. **评分只计 B1..B5 五个买入指标，各 +20，满分 100**；**X1 不计分**（其"BB 上穿"分支与 B5 重叠，避免重复计分），但 X1 仍作为买入信号列出。
3. **评分为"逐根"而非"逐信号"**：同一根上命中的买入指标越多，该根分数越高；同根多条买入信号共享该根总分（符合"总分越高买入信号越强"）。
4. **"预警的股票是持仓股"** → 直接取做T页「📋 持仓池」（`SsaT0PoolStore`）。池为空时浮窗不出现。
5. **收益率口径**：区间 = 末 120 根 1H；收盘价成交；单边做多最多一仓；末根强平；默认**不扣费**（`includeCost=false`），费用仅为可选展示。
6. **"退出软件后出现"** 采用 `MainActivity.onStop()` 触发（含切到其他 App 的场景），`onStart()` 收起。这是 Android 上最接近"退出即显示"的可行时机。
7. **浮窗刷新节奏**：打开时先渲染本地缓存（秒开），缓存超 10 分钟或为空才联网；之后**盘中每 5 分钟**重算一次，非交易时段不重算（省电/省流量），用户随时可点「更新」强制重算。
8. **前台服务类型用 `specialUse`**（不用 `dataSync`，避免 6 小时超时限制）；不取 WakeLock。
9. **无权限绝不起服务**：`start()` 前置自检，避免 `BadTokenException` 崩溃。
10. **`START_STICKY` + `onTaskRemoved` 不 `stopSelf`**：保证"退出软件后浮窗常驻"。
11. 浮窗 UI 文案精简，避免遮挡；可拖拽，位置不持久化（重启回到左上默认位）。

## 7. 风险清单（Risks）

| 风险 | 说明 | 对策 |
|------|------|------|
| 无 `SYSTEM_ALERT_WINDOW` 授权 | 部分 ROM 需二次设置；未授权起服务必崩 | `start()`/`onCreate()` 双重 `Settings.canDrawOverlays` 自检；UI 引导跳设置页 |
| Android 14 前台服务类型校验 | `specialUse` 未声明 subtype 会抛异常 | Manifest `<property>` 显式声明 `stock_alert_overlay` |
| `startForegroundService` 5s 超时 | 未及时 `startForeground` 会 ANR/崩溃 | `onStartCommand` 中先 `startForeground` 再拉数据 |
| 新浪接口限流 | 持仓池多票串行拉 200 根（每票 ~500KB） | 串行 + 单票异常隔离 + 5 分钟节流 + 本地缓存优先渲染 |
| 末根 1H 未收盘 | 交易时段末根信号会变 | 沿用既有「末根未确认」提示；浮窗显示更新时间 |
| 评分与手续费口径误解 | 用户可能希望扣费后收益 | 收益率卡明确标注「未扣费(毛)/已扣费」，`AlertParams.includeCost` 可切 |
| 浮窗与 App 内页面数据不一致 | 缓存 vs 实时 | 浮窗显示 `updated` 时间戳；点「更新」强制重算 |
| View 泄漏 | 服务销毁未移除 overlay | `onDestroy` 中 `view.detach(wm)`；`stop` 路径统一走 `detach` |
| 拖拽误触发表情切换 | `ACTION_UP` 误判为点击 | 位移阈值 `dp(8)`；超阈值标记为拖拽并消费点击 |
